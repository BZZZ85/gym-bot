# GYM — Telegram Mini App

Дневник тренировок для существующего Telegram-бота: запись веса и повторений по подходам, таймер отдыха, история и график прогресса. Интерфейс адаптируется к телефону и компьютеру.

Приложение использует таблицы `users` и `records` того же PostgreSQL, что и бот. Сохранённые в приложении подходы видны в боте; старые записи бота доступны в приложении. Команда `python start.py` запускает бота и веб-приложение вместе в одном сервисе.

## Локальный запуск

Требуется Python 3.11 и PostgreSQL. Команды выполняются из корня проекта.

```sh
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN` и `DATABASE_URL`. Уже существующий `ton.env` также поддерживается. Переменные окружения сервиса имеют приоритет над файлами. Если оба файла заданы, `ton.env` имеет приоритет над `.env`.

```sh
python start.py
```

Откройте `http://127.0.0.1:8000/?demo=1`, чтобы посмотреть приложение. Демо содержит пример тренировок и сохраняет изменения в локальном хранилище браузера, отдельно от настоящей базы. Для настоящего входа приложение нужно открыть из Telegram-бота по публичному HTTPS-адресу.

Общий запуск требует полного `requirements.txt`.

## Подключение на Railway

Если используете готовый архив `gym-railway-ready.zip`, распакуйте его и загрузите **содержимое** в корень репозитория GitHub с заменой старых файлов. Сам ZIP загружать в репозиторий не нужно. Проверьте наличие `webapp/static/index.html`, `webapp/static/app.js` и `webapp/static/styles.css`: это интерфейс, без этих файлов веб-сервис не запустится.

1. Обновите репозиторий на GitHub, включая `start.py`, `railway.toml`, папку `webapp`, `requirements.txt`, `Procfile`, `.python-version` и `runtime.txt`.
2. В существующем сервисе бота задайте `BOT_TOKEN`, рабочий `DATABASE_URL` и `RAILPACK_PYTHON_VERSION=3.11`. Секреты задаются в Variables, файлы `ton.env` и `.env` не загружаются в репозиторий. Внутренний адрес PostgreSQL доступен сервисам того же проекта и окружения Railway. Для базы из другого проекта используйте её публичный адрес подключения.
3. В Settings задайте Start Command:

   ```sh
   python start.py
   ```

4. В Networking нажмите Generate Domain и выполните Redeploy. Запуск автоматически использует `RAILWAY_PUBLIC_DOMAIN` для кнопки приложения. Можно явно задать `WEBAPP_URL=https://ваш-домен`, например для собственного домена.
5. Healthcheck Path: `/health`. `railway.toml` уже задаёт эту проверку, общую команду запуска и одну реплику сервиса.
6. Дождитесь успешного запуска, отправьте `/start` в личном чате с ботом, откройте «Открыть приложение», сохраните подход и проверьте его в истории приложения и бота.

При запуске веб-сервиса недостающие таблицы создаются автоматически. Для защиты повторных запросов добавляется таблица `miniapp_submissions`; существующие тренировки не переписываются.

`start.py` сначала запускает веб-приложение и ждёт готовности базы через `/health`, затем запускает бота. При остановке сервиса завершаются оба процесса. Если один процесс падает или неожиданно завершается, общий запуск заканчивается с ошибкой для перезапуска Railway. `Procfile` также использует общий запуск. PostgreSQL подключается через `DATABASE_URL`.

## Как работают данные

- Сервер проверяет HMAC-подпись Telegram `initData` и срок действия (24 часа). Идентификатор пользователя берётся только из проверенных данных Telegram.
- Все запросы к тренировкам ограничены этим пользователем. Клиентские `user_id` не принимаются.
- Один подход — одна запись в `records`. Сохранение нескольких подходов выполняется одной транзакцией.
- Повтор запроса с тем же `request_id` не создаёт повторных записей.
- Вес 0 кг поддерживается для упражнений с собственным весом. Повторения — целые числа от 1 до 1000; вес — от 0 до 2000 кг; до 30 подходов в одной записи.
- Нулевые записи, которые старый бот создавал при добавлении упражнения, не учитываются как тренировки.
- Поддерживаются старые записи с несколькими повторениями/весами через пробел.
- Тренировки группируются по календарным дням в `Europe/Moscow`. Старые `TIMESTAMP` без часового пояса интерпретируются как UTC, что соответствует обычной конфигурации PostgreSQL на Railway. Если база ранее работала в другом часовом поясе, перед запуском требуется проверить её исторические даты.
- График показывает максимум веса за день, до 20 последних дней тренировок. История показывает 30 последних дней с тренировками.
- Таймер сверяется с текущим временем и корректно обновляется при возвращении в приложение; звук и фоновые уведомления не используются.

## Проверки

```sh
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
node --check webapp/static/app.js
node tests/check_client.cjs
```

Тесты используют фиктивную базу и отдельный тестовый токен. Они не подключаются к настоящему PostgreSQL и не запускают бота. Проверяют подпись, срок входа, границы данных, доступ только к собственным записям, повторное сохранение и совместимость старых записей.

Перед публикацией дополнительно проверьте `/health`, запись и чтение на тестовой базе PostgreSQL и открытие в Telegram на телефоне.
