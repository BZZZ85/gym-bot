# GYM — приложение для тренировок

Приложение для Telegram: запись веса и повторений по подходам, таймер отдыха, история тренировок и график прогресса. В проекте запускается только веб-сервер. Код бота и его зависимости убраны из активной версии.

## Запуск на Railway

1. Распакуйте gym-app-ready.zip. Загрузите распакованные файлы в корень репозитория GitHub с заменой старых. Удалите из репозитория старые bot_mvp.py и db.py; они больше не используются.
2. В Railway подключите этот репозиторий к одному сервису. Start Command: python start.py. railway.toml и Procfile уже содержат эту команду.
3. В Variables задайте BOT_TOKEN, DATABASE_URL, RAILPACK_PYTHON_VERSION=3.11 и PORT=8080. DATABASE_URL указывает на вашу существующую PostgreSQL. BOT_TOKEN используется только для проверки входа в Telegram Mini App.
4. В Settings → Networking → Generate Domain создайте HTTPS-домен. Target Port должен совпадать с PORT: 8080.
5. Выполните Redeploy. По адресу /health ожидается ответ {"status":"ok"}.
6. Чтобы открывать приложение внутри Telegram, в BotFather выполните /setmenubutton, выберите своего бота и задайте HTTPS-адрес приложения и название кнопки «Тренировки». Для этой кнопки отдельный работающий процесс бота не требуется.

WEBAPP_URL для запуска веб-приложения не нужен. База PostgreSQL подключается через DATABASE_URL; данные прежних тренировок сохраняются.

## Просмотр и локальный запуск

Для демонстрации откройте адрес приложения с /?demo=1. Демо содержит пример тренировок и сохраняет изменения только в браузере. Настоящие записи доступны при входе через Telegram.

Для запуска требуется Python 3.11:

    python -m venv .venv
    python -m pip install -r requirements.txt
    python start.py

Скопируйте .env.example в .env и задайте BOT_TOKEN и DATABASE_URL. Поддерживается также существующий ton.env. Переменные окружения имеют приоритет над файлами. PORT по умолчанию равен 8080.

## Данные и вход

- Telegram initData проверяется по HMAC-подписи и сроку действия 24 часа. Токен не попадает в интерфейс.
- Записи ограничены проверенным идентификатором пользователя. Данные других пользователей недоступны.
- Подходы сохраняются одной транзакцией; повтор того же request_id не создаёт дублей.
- Вес от 0 до 2000 кг, целые повторения от 1 до 1000; до 30 подходов в одной записи. Нулевой вес подходит для упражнений с собственным весом.
- Старые нулевые записи упражнений не считаются тренировками. Списки повторений и весов через пробел поддерживаются.
- Тренировки группируются по московскому времени. Старые TIMESTAMP без часового пояса считаются UTC, как в стандартной конфигурации PostgreSQL Railway.
- История показывает 30 последних дней тренировок, график — 20 последних тренировочных дней.

## Интерфейс и проверки

Меню содержит «Тренировка», «История», «Прогресс» и отдельную кнопку записи. Поиск учитывает русские названия и варианты е/ё. Таймер остаётся видимым при переключении экранов и обновляется при возвращении в приложение.

webapp/static содержит HTML, CSS и JavaScript. В webapp/main.py встроена резервная копия всего интерфейса, поэтому отсутствие папки static при ручной загрузке не мешает открыть приложение. После изменения интерфейса обновите копию:

    node scripts/build_frontend.cjs

Проверки:

    python -m pip install -r requirements-test.txt
    python -m unittest discover -s tests -v
    node --check webapp/static/app.js
    node tests/check_client.cjs

Python-тесты используют фиктивную базу и тестовый токен. Перед публикацией проверьте запись подходов на тестовой PostgreSQL и открытие приложения в Telegram на телефоне.

Файлы ton.env, .env, архивы и .review не загружаются в репозиторий. Старый код локально сохранён в .review/legacy-bot и не входит в новую сборку.
